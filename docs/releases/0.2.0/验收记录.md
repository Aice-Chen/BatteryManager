本轮真实升级发现并修复了静默安装丢失自启项的问题：原先在任务列表创建前设置勾选，后续被 Inno 重置。新实现直接按当前 Run 状态生成默认值，显式任务选择仍交由安装器处理，并保护未知同名启动项。回退到含旧问题的 preview.2 时显式选择自启；恢复 0.2.0 时不传此选项，确认其保留当前登记。

程序内升级的 HTTP 响应由显式本地 fixture 提供，使用实际 0.2.0 安装包，下载、校验、存储和进程交接均真实执行。安装器检查时旧进程已经终止，持有的进程句柄返回结束状态；本轮不把这一结果写成等待仍在运行的进程已获覆盖。

GitHub 远端 CI 已启用，按 PR 和 main 提交触发，避免同一开发提交重复运行；每个提交的实际结果见 [GitHub Actions](https://github.com/Aice-Chen/BatteryManager/actions/workflows/verify.yml)。

首轮云端检查发现一项测试样本在关闭换行转换后未重新检出，CI 复制出的 CRLF 脚本因此被源码校验拒绝。已修正样本准备，并增加真实 CRLF 输入下的切换前、拒绝与重新检出断言；生产校验规则未放宽。

首次真实 Windows 注销后登录测试未通过：重新登录后没有应用进程，工具直接读取与独立系统提供者读取的启动/卸载登记不一致；用户也确认 Windows 启动列表无应用。具体差异机制尚未查明。随后用户从普通桌面启动程序并登记启动项，系统列表和独立查询已可见，再由用户开启 Windows 开关；这不等于已经通过登录自启复测。

本机 Windows 开关的原始值实测为关闭 `01 00 00 00 …`、开启全零的 12 字节记录。App 与安装器补齐这两种格式，保留既有 2/3 兼容及其他格式未知处理，并继续只读系统许可。迁移到用户选定的安装目录后仍需核对系统登记和真实登录启动。

安装版统一后的定向验证：Application 210 项、App.Logic 110 项通过，应用构建通过；管理页 26 项、安装器隔离检查 10 项、发行规则 24 项、假 GitHub 发布检查 51 项通过。安装器检查包含上述两份实际字节样本的分类及许可原值保留；发布检查确认只上传四项公开附件，内部负载仍与源码提交绑定。未重复协议开关、系统睡眠或历史像素测试。

尚待单独完成：新的安装目录迁移、修正后的真实 Windows 登录自启、正式发布后的真实下载。程序与安装器尚未签名。当前用户配置、硬件日志、详细路径和截图留在本机证据目录，不进入公共仓库或发行附件。
